# Architecture Decision Records

This directory records decisions that materially affect AcheNaki?'s architecture, operations, security, or developer workflow.

Use short Markdown records with sequential names, for example:

- `0001-local-development-strategy.md`
- `0002-database-ownership.md`

Each record should state the context, options considered, decision, and consequences. A record may be marked pending when evidence is insufficient. If a decision changes, preserve the earlier record and document the superseding decision rather than silently rewriting history.

Create an ADR only when a decision has meaningful alternatives or lasting consequences.
